# Prototype To Swimlane Mermaid

使用本 skill 将产品原型图和业务需求转化为 Mermaid `swimlane-beta` 泳道图。

目标不只是表达业务逻辑，还要尽量生成适合导出 SVG、后续在 Figma 中复现的清晰泳道图。

## 工作流程

### 1. 查看原型和需求

当用户提供 Figma 链接、截图或业务描述时，先理解原型和业务逻辑。

需要识别：

- 页面和状态。
- 用户操作。
- 系统状态变化。
- 后台运营操作。
- 判断节点和分支。
- 成功、失败、拒绝、终止状态。
- 可撤销、可取消、可回退阶段。
- 原型中的备注或说明文字。

如果用户提供 Figma 链接，必须先查看对应节点，再开始梳理流程。

### 2. 先确认泳道角色

在执行 Mermaid 代码、节点清单、连线清单之前，必须先和用户确认：

- 一共有几条泳道。
- 每条泳道分别是什么角色。
- 泳道从左到右的顺序是什么。

如果用户没有明确说明，先询问用户。不要直接默认开始绘制。

常见默认候选为：

- `用户`
- `系统`
- `后台运营`

但只有在用户确认后才能作为最终泳道使用。

### 3. 先澄清业务疑问

以下信息不明确时，必须先提问：

- 真正的开始节点是什么。
- 真正的结束节点是什么。
- 某个动作属于哪个角色。
- 某个流转是系统自动完成，还是人工审核。
- 后台运营是否需要审核。
- 审核拒绝后发生什么。
- 用户是否可以取消、撤回或中止申请。
- 商品卡片、订单卡片或详情页显示什么状态。
- 哪些状态对用户可见。
- 退款、退货、状态更新是即时完成还是延迟完成。

提问要具体，并且能直接影响泳道图结构。

如果存在未确认的问题，只输出问题并等待用户回答，不要继续绘制泳道图。

### 4. 设计布局再输出 Mermaid

用户确认泳道和关键业务规则后，先在内部设计布局，再输出 Mermaid `swimlane-beta` 代码。

默认规则：

- 方向使用纵向：`swimlane-beta TB`。
- 按业务逻辑从上到下绘制。
- 开始节点必须匹配用户确认的业务开始点。
- 节点文案简短、清晰、可读。
- 审核、判断、是否通过等逻辑使用判断节点。
- 分支必须有明确标签，例如 `通过`、`拒绝`、`退款到账前可取消`。
- 关键状态变化必须单独表达为系统节点。
- 节点文字尽量沿用原型图或用户需求中的产品语言。

如果英文状态词是产品界面中的正式文案，需要保留英文，例如：

- `Return requested`
- `Return approved`
- `Refund processing`
- `Refunded`
- `Delivered`
- `Tracking Number`
- `Refund completed / Return Details`

### 5. Mermaid 布局优化规则

必须遵循以下七条布局优化方向：

1. 使用 `swimlane-beta TB` 作为默认方向，确保泳道图从上到下阅读。
2. 优先保证布局可读性：主流程尽量在同一泳道内纵向推进，跨泳道箭头只在职责确实发生转移时出现。
3. 减少远距离回流线：不要让多个分散在不同高度的节点都直接连向同一个底部或顶部节点；优先使用局部汇聚节点、统一取消判断节点或节点说明来收束。
4. 避免一个判断节点承担太多出入线：判断节点前尽量只有一个直接前置节点，判断节点后只表达核心分支。
5. 用中转节点控制跨泳道路径：跨泳道动作优先采用“触发节点 -> 接收/处理节点 -> 判断节点”的结构，避免直接从远处跨泳道连到判断节点。
6. 输出前进行布局自检：检查是否存在长箭头、交叉线、箭头穿过节点文字、判断节点入线过多、跨泳道线跨度过大等问题，并主动改写 Mermaid 结构。
7. 复杂场景可输出两个版本：`业务完整版本` 和 `布局优化版本`。当二者冲突时，先保证业务完整，再提供更适合导出 SVG 和 Figma 复现的布局优化版本。

当流程包含多个泳道、判断分支、回退线或取消线时，读取 `references/layout-optimization-template.md`，参考其中的 Mermaid 结构模板组织节点和连线。

### 6. 输出节点清单

在 Mermaid 代码之后，按泳道输出节点清单。

格式：

```text
节点清单：
用户：
- ...

系统：
- ...

后台运营：
- ...
```

节点清单是后续 Figma 复现时的流程真值之一。

### 7. 输出连线清单

在节点清单之后，输出连线清单。

格式：

```text
连线清单：
- A -> B
- C --通过--> D
- C --拒绝--> E
```

连线清单必须覆盖 Mermaid 图中的所有主流程、分支流程、回退流程和取消流程。

### 8. 输出布局自检结果

在复杂流程中，连线清单之后输出简短的布局自检结果。

重点说明：

- 是否已减少远距离箭头。
- 是否已避免判断节点入线过多。
- 是否已使用中转节点控制跨泳道连线。
- 是否存在仍需用户接受的布局取舍。

## 默认输出结构

如果存在疑问：

```text
一、需要确认的问题
```

如果信息已确认：

```text
一、Mermaid swimlane-beta 代码
二、节点清单
三、连线清单
四、布局自检结果
```
